# 决策：让五个页面共享一套清晰、克制的功能层

- 状态：已实施
- 日期：2026-07-30
- 负责人：FocusTrace
- 主要产品支柱：看清

## 问题

同一个主窗口已经通过系统导航标题说明当前位置，但部分页面仍在内容区重复标题；卡片、工具条和主要按钮又各自使用不同的圆角、填充和强调方式。用户在需求箱、时间轴和回顾之间切换时，需要重新判断“哪里是页面标题、哪里是当前行动、哪里只是内容”，增加了与工作无关的视觉决策。

## 预期结果与证据

完成后，每个页面只有一个系统页面标题；内容区最多保留一条说明当前目的与主要行动的工具栏。所有主要内容卡、分组标题和主要按钮复用同一组语义组件。macOS 26 及以上只在导航、工具栏、主要行动和临时确认等功能层使用玻璃材质，数据图表与正文保持稳定实体表面。

证据：

- 需求箱不再重复显示“需求箱”标题，入口与说明仍完整；
- 五个主页面的内容卡圆角、边框和层级来自同一组件；
- macOS 14–25 使用无功能缺失的现有材质回退；
- Reduce Transparency 开启时不依赖透明度表达状态；
- 既有日期弹层、单窗口、菜单栏紧凑度和时间轴性能契约保持通过。

## 边界

- 本次明确不解决：重做信息架构、增加页面、把所有内容改成玻璃、模拟 iOS 视觉、改变时间轴配色。
- 新增数据及用途：无。
- 明确不采集：窗口标题、URL、输入内容、聊天对象、手机行为。
- 必须由用户确认的决定：无；这是既有层级和组件的兼容性收敛。
- 数据不足、失败或权限缺失时的降级：系统不支持新玻璃 API或用户降低透明度时，使用高对比实体填充与边框。

## 完整流程

1. 触发：用户切换到任一主页面。
2. 唯一主要行动：在页面首个功能层找到当前最重要的操作。
3. 反馈：选中态、按钮态和内容卡层级使用一致视觉语义。
4. 中断后的恢复：返回页面时，系统导航标题与首要行动位置不变。
5. 完成或退出：操作完成后回到原页面，不新增中间状态。
6. 验证：窄窗口、深浅色、降低透明度和 macOS 14 回退均可读且无布局漂移。

## 技术与回归

- 业务规则位置：`FocusTraceTheme` 的功能层、内容层和主要行动组件。
- 新增单元测试：组件与页面结构仓库回归；可用性回退契约。
- 保护的既有回归测试：UX-01 至 UX-10，尤其日历弹层、单窗口、展开命中区和趋势图边界。
- 性能工作负载与预算：不在每秒时钟刷新中重建玻璃容器；时间轴仍按分钟/数据版本缓存。
- 数据迁移与回退：无数据变更；删除新组件修饰即可回退。

## 发布切片

统一页面工具层、内容卡与主要按钮；只在支持的平台为功能层启用玻璃，保持内容层和旧系统回退不变。
