# 决策：用多证据判断切换负荷，而不是生成“脑负荷分数”

- 状态：已接受
- 日期：2026-07-29
- 负责人：FocusTrace
- 主要产品支柱：看清 / 不丢 / 改善

## 问题

当前日报分别展示应用切换、工作流跳转、返回点和训练难度，但没有把它们组织成一个可执行的切换负荷判断。用户容易把切换总数当成脑部负担，也无法知道真正需要改变的是工具碎片、未完成任务的注意残留，还是切走后的恢复方式。

单个行为计数不能测量脑活动、脑损伤或临床意义上的认知负荷。当天甚至可能存在语义跳转记录而没有足够的有效工作分钟；这时根据跳转数给结论会制造伪精确。

## 预期结果与证据

完成后，日报先回答“今天能否判断”，再分别展示：

1. 应用碎片是否较个人基线上升；
2. 跨工作流切换是否缺少明确边界并产生短停留、快速返回；
3. 保存返回点是否降低恢复负担；
4. 主观专注难度和训练结果是否与行为信号一致。

只有行为、恢复和主观/结果证据至少两类收敛，才显示“切换负荷升高”；否则显示“仅有行为信号”“尚在校准”或“不可判断”。成功证据是日报不再从切换总数直接给出注意力或脑负荷结论，并且每天只建议一个可在下一工作日验证的交接实验。

## 边界

- 本次明确不解决：脑活动监测、脑损伤判断、ADHD 诊断、疲劳或压力的医学评估。
- 新增数据及用途：不新增原始采集；只聚合既有应用片段、工作流区间、最终跳转、跳转原因、导航事件数、返回点、分心返回耗时、训练结果与 1–5 主观难度。
- 明确不采集：摄像头、瞳孔、心率、HRV、脑电、窗口标题、URL、输入内容、聊天对象和返回点文字。
- 必须由用户确认的决定：训练计划、提醒策略、允许应用和工作流绑定仍不得由日报自动修改。
- 数据不足、失败或权限缺失时的降级：显示不可判断或仅有行为信号，只建议补齐一项测量，不给行为矫正结论。

## 完整流程

1. 触发：官方聚合器生成每日回顾。
2. 唯一主要行动：从最高可信的负荷证据中选择一个交接动作实验。
3. 反馈：显示负荷状态、可信度、主要驱动和用到的 trace 家族。
4. 中断后的恢复：优先使用“离开前写下回来后的第一步—保存返回点—返回后执行”的 ready-to-resume 流程。
5. 完成或退出：下一工作日检查同一路线的返回、目的停留或主观难度；证据不足时继续观察，不升级提醒。
6. 验证：比较个人基线与实验后的单一指标；至少 5 次可比训练或足够路线样本后再调整长期计划。

## 技术与回归

- 业务规则位置：`Sources/FocusTraceCore/SwitchingLoadEngine.swift`。
- 新增单元测试：无数据拒绝判断、同工作流工具切换不误判、跨目标高恢复负担、多证据收敛、trace 覆盖。
- 保护的既有回归测试：日报隐私、旧 schema 读取、单一建议、工作流语义门槛、时间轴性能和固定最小采集。
- 性能工作负载与预算：2,000 个应用片段、1,000 条语义跳转和 1,000 个返回点小于 1 秒。
- 数据迁移与回退：日报升至 schema v6 并新增聚合字段；v2–v5 继续可用于 Codex 写回。回退时忽略新字段即可，不迁移本地 store。
