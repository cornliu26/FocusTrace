# 决策：把专注提示与切换确认收敛到同一个右侧浮层

- 状态：已被 `2026-07-28-analysis-driven-switch-intervention.md` 取代
- 日期：2026-07-28
- 负责人：FocusTrace
- 主要产品支柱：不丢

## 问题

FocusTrace 当前在屏幕右侧用细轨和卡片提示连续专注，却在屏幕顶部中央用另一套弹窗确认工作流切换。两者都在回答“现在的注意力上下文发生了什么”，但位置、尺寸、材质和出现方式不同。用户需要先识别是哪一种 UI，无法形成稳定的空间预期。

居中弹窗还暗示系统正在阻断操作，但 FocusTrace 并不拦截 macOS Space 手势。这种视觉语义与真实行为不一致。

## 预期结果与证据

用户只需记住一个位置：FocusTrace 的实时注意力反馈始终出现在屏幕右侧。

- 正常工作时显示低存在感的五分钟进度细轨；
- 达到里程碑或切换过密时在原位置展开提醒卡片；
- 工作流切换需要决定时在原位置展开可点击的决策卡片；
- 任一时刻只出现一种状态，不再有顶部弹窗与右侧边栏交替。

验收时，三种状态的右边缘和垂直中心一致，使用同一材质、圆角和边界；切换决策的三个按钮、10 秒超时和连续导航规则保持不变。

## 边界

- 本次明确不解决：拦截 Space 手势、增加新的提醒类型、修改提醒阈值、重新设计训练规则。
- 新增数据及用途：无。
- 明确不采集：窗口标题、URL、输入内容、聊天对象、屏幕内容和手势数据。
- 必须由用户确认的决定：工作流切换原因仍由用户点击确认。
- 数据不足、失败或权限缺失时的降级：浮层无法显示时不阻断系统操作，既有超时与本地记录继续工作。

## 完整流程

1. 触发：连续工作、达到里程碑、工作流切换过密或 Space 工作流变化。
2. 唯一主要行动：普通状态无需操作；切换决策状态只选择一个原因或滑回原桌面。
3. 反馈：同一个右侧浮层按事件重要性从细轨展开为提醒或决策卡片。
4. 中断后的恢复：连续 Space 导航时决策卡保持原位并显示正在确认最终桌面。
5. 完成或退出：提醒自动收起；决策在确认、取消或超时后回到当前工作流进度细轨。
6. 验证：共享几何与视觉契约测试、切换状态机测试和真实界面截图/点按验收。

## 技术与回归

- 业务规则位置：`AttentionCueOverlayController.swift`、`SpaceSwitchGateController.swift`、`FocusTraceAttentionSurfaceLayout.swift`。
- 新增单元测试：共享右侧锚点、三态视觉入口和切换后恢复。
- 保护的既有回归测试：切换门完整 10 秒、连续导航不闪退、无阴影、可访问性按钮、性能与单窗口。
- 性能工作负载与预算：不增加面板数量、计时器或轮询；只共享布局常量和视觉样式。
- 数据迁移与回退：无数据迁移；回退布局文件和两个视图样式即可。
