# 决策：用五个可解释维度替代零散数字与单一总分

- 状态：已被 `2026-07-29-longitudinal-attention-experiments.md` 取代
- 日期：2026-07-29
- 负责人：FocusTrace
- 主要产品支柱：看清 / 改善

## 问题

回顾页已经有建议、切换干预、阶段 2 和明细数字，但用户仍无法在一次浏览中回答三个问题：今天的注意力是否稳定、问题具体发生在哪个环节、应该先改善什么。继续堆叠切换次数或生成更长文字，只会增加解释负担。

## 预期结果与证据

用户打开回顾页后，先看到一个固定的五维看板，并能在 10 秒内区分：

1. 稳定推进：同一工作流内连续专注是否较个人基线变化；
2. 碎片控制：高碎片五分钟窗口是否增加，并区分同工作流工具协作；
3. 切换边界：最终工作流切换中，计划边界、无结构或被迫切换各有多少；
4. 恢复能力：保存返回点后是否真正返回，以及恢复耗时；
5. 训练反馈：目标完成结果和主观难度是否共同支持调整训练。

每个维度必须显示当前值、个人基线或样本门槛、数据可用状态和最多两条解释。看板不得生成总分。效果以“用户能从看板指出一个具体问题，并与当天唯一建议一致”为验收，而不是以图表数量验收。

碎片控制不能只依赖个人基线，否则长期高碎片会被错误地显示为“正常”。当至少 4 个有效五分钟窗口中，有至少 3 个且过半达到既有“6 次切换 / 5 分钟”高碎片刻度，并且同工作流工具协作占比不足 70% 时，卡片可标记为“需关注”。这是产品显示灵敏度，不是临床阈值。

## 边界

- 本次明确不解决：脑活动、前额叶负荷、脑损伤或 ADHD 的测量与诊断；跨设备或手机行为；自动修改训练计划。
- 新增数据及用途：不新增采集；只复用既有日聚合、个人基线、切换语义、返回点和训练反馈。
- 明确不采集：窗口标题、网页地址、聊天对象、键盘内容、需求正文和返回点文字。
- 必须由用户确认的决定：训练计划调整仍沿用现有确认流程；看板只呈现证据。
- 数据不足、失败或权限缺失时的降级：单个维度独立显示“待收集”或“校准中”，并说明缺少的样本；不得用其他维度代填，也不得输出整体好坏。

## 完整流程

1. 触发：用户打开“回顾分析”或切换日期。
2. 唯一主要行动：先阅读五维看板，找到唯一标为“需关注”的维度。
3. 反馈：对应卡片给出值、相对个人基线的变化、样本和原因。
4. 中断后的恢复：日期变化、数据写入或跨分钟后重算；同一分钟且数据未变时复用缓存。
5. 完成或退出：用户向下查看“今天唯一建议”，决定是否执行；关闭页面不会修改任何计划。
6. 验证：五个维度固定存在、分项门禁生效、无总分、同工作流工具切换不被直接判为分心、现有切换干预指标被看板承接。

## 技术与回归

- 业务规则位置：`FocusTraceCore/AttentionDashboardEngine.swift`；SwiftUI 只渲染聚合结果。
- 新增单元测试：五维筛选、分项门禁、同工作流工具切换反例、训练样本门槛。
- 保护的既有回归测试：REVIEW-01、REVIEW-05、REVIEW-08、ATT-02、PRIV-01。
- 性能工作负载与预算：分析报告与看板按所选日期、数据版本和分钟缓存；固定大样本完整日报与看板生成小于 1 秒。
- 数据迁移与回退：不新增持久化字段；移除看板即可回退，历史数据与报告协议保持可读。
