# 决策：让数据与保留操作按决策顺序排列

- 状态：已采用
- 日期：2026-07-29
- 负责人：FocusTrace
- 主要产品支柱：改善

## 问题

“数据与保留”把保留期单独放在卡片最右侧，又把导出和删除四个同色按钮堆在左下角。用户无法快速区分设置、普通操作与危险操作，需要额外寻找和判断。

## 预期结果与证据

用户从上到下依次完成“保留多久、是否导出、是否删除”的判断；三类操作拥有一致的左右对齐关系，删除操作有明确但克制的危险色。通过界面回归确认三行结构、操作顺序和二次确认均未退化。

## 边界

- 本次明确不解决：导出格式、保留策略、删除范围和恢复机制。
- 新增数据及用途：无。
- 明确不采集：无新增采集。
- 必须由用户确认的决定：删除所选日期和清空全部仍需二次确认。
- 数据不足、失败或权限缺失时的降级：沿用现有导出与删除反馈，不新增后台动作。

## 完整流程

1. 触发：用户进入“设置与数据”，查看“数据与保留”。
2. 唯一主要行动：在对应行调整保留期、导出副本或发起删除。
3. 反馈：控件与所属说明保持同一行；删除使用危险色。
4. 中断后的恢复：关闭菜单或取消确认框即可回到原状态。
5. 完成或退出：只有明确选择保留期、完成导出或确认删除时才产生变化。
6. 验证：源码交互回归、完整测试和本机视觉验收。

## 技术与回归

- 业务规则位置：不变；本次仅调整 `SettingsView` 的呈现结构。
- 新增单元测试：无新的业务规则。
- 保护的既有回归测试：新增数据设置三行布局及危险操作层级的呈现回归；保留既有删除确认。
- 性能工作负载与预算：静态设置页，无新增持续计算。
- 数据迁移与回退：无迁移；可单独回退布局。

## 发布切片

仅重排“数据与保留”卡片，复用原有四个动作、状态和确认流程。
