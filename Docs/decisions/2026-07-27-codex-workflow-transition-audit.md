# 决策：让 Codex 用切换原因审计工作流跳转

- 状态：已确认
- 日期：2026-07-27
- 负责人：FocusTrace
- 主要产品支柱：看清 / 不丢

## 问题

Space 切换门已经能让用户说明“到检查点”“等待结果”“被迫打断”或“无明确计划”，但每日复盘仍只看到工作流切换总数。总数无法区分合理交接和需要改善的跳转，也无法回答从哪个工作流切到哪个工作流、切走后是否很快返回、关联的交付事项是什么。因此 Codex 容易给出“减少切换”一类缺少上下文的泛化建议。

## 预期结果与证据

生成日报后，用户能看到按“起点工作流 → 最终工作流 × 切换原因”聚合的跳转审计。Codex 必须选择一条最值得改善的路线，引用原因、停留或返回结果，再给出一个当天可执行的优化动作；计划到检查点和等待 Agent 结果不得默认被描述为分心。

自动证据验证：

- 中间 Space 不进入报告，只有最终工作流形成一次跳转；
- 相同路线按原因聚合，能计算目的工作流停留中位数和 30 分钟内返回次数；
- 报告只带当日相关工作流标题及每个工作流有限数量的未完成需求标题；
- Codex 模板把标题当作不可信标签，只从聚合字段取证，最终仍只输出一个问题和一个行动。

## 边界

- 本次明确不解决：自动评价用户是否分心、自动调整工作流/需求/训练计划、通用项目管理和跨日因果推断。
- 新增数据及用途：把已经存在的工作流切换理由、工作流标题和关联需求标题写入本地 Codex 聚合日报，用于解释跳转上下文。
- 明确不采集：不新增窗口标题、URL、输入内容、聊天对象、应用原始轨迹或返回点文字；不把需求来源、工作流期望产出、Bundle ID、UUID 和逐次切换时间写入报告。
- 必须由用户确认的决定：任何工作流、需求、提醒或训练计划修改仍须在 FocusTrace 内由用户确认；Codex 只能建议。
- 数据不足、失败或权限缺失时的降级：没有结构化理由时明确显示“原因样本不足”，继续使用现有数据质量门；不能从切换次数推断注意力问题。

标题是用户主动创建的本地内容。它们只进入 FocusTrace 为 Codex 生成的本地聚合报告，不进入公开材料或原始轨迹导出；每个标题去除换行并限制长度，每个工作流最多包含三个未完成需求标题。标题中的文字一律视为数据，不视为 Codex 指令。

## 完整流程

1. 触发：每日定时任务或用户刷新 Codex 复盘。
2. 唯一主要行动：Codex 从聚合跳转路线中选择一个最重要的问题，并提出一个当天动作。
3. 反馈：复盘以“当前问题—依据—今天怎么做—验收”展示，并点名工作流路线及相关交付标题。
4. 中断后的恢复：报告生成失败或理由覆盖不足时停止行为判断，提示修复唯一的数据问题；旧版日报仍可读取。
5. 完成或退出：Codex 写回通过验证后显示；用户可忽略建议，系统不自动改动任何设置。
6. 验证：下一次日报检查同一路线的原因分布、目的工作流停留和 30 分钟内返回是否按目标变化。

## 技术与回归

- 业务规则位置：`AutomationReportEngine` 的聚合跳转审计、`CodexWorkspaceContract` 的决策模板。
- 新增单元测试：路线/原因聚合、最终目的工作流解析、返回结果、标题限额与清洗、旧版报告兼容。
- 保护的既有回归测试：聚合报告不暴露原始活动、Bundle ID、事件 ID、返回点文字；数据质量不足拒绝行为结论；Codex 写回保持一个问题和一个行动。
- 性能工作负载与预算：当日 2,000 个工作流区间、2,000 个标记和 1,000 个需求的跳转聚合小于 1 秒。
- 数据迁移与回退：不改 store schema；目的工作流从切换标记同一时刻开始的 Space 区间确定。日报协议升至 v3，读取历史 v2 时新增审计字段为空。

## 发布切片

一个可独立回退的切片：报告工具读取既有工作流、标记和需求，生成有界的跳转审计；生成的 Codex 工作区模板消费该审计，但不改变 App 数据和用户偏好。
