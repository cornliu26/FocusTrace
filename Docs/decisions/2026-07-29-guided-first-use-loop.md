# 决策：首次使用必须走完创建、绑定、记录和回顾

- 状态：已采用
- 日期：2026-07-29
- 负责人：FocusTrace
- 主要产品支柱：看清

## 问题

旧流程在创建第一个工作流后立即关闭首次设置，但真正决定能否形成可靠轨迹的“从状态栏绑定工作桌面”只存在于另一份帮助说明。新用户容易以为创建完成就已经开始按工作流记录，直到第二天才发现时间轴没有可靠归因。

## 预期结果与证据

首次创建后，用户在同一个不可跳过的流程中看到下一步绑定方法、正常记录方式和回顾出口；中途退出再打开时能从已有工作流继续，而不是重复创建。App 内教学和 README 使用“创建 → 绑定 → 工作 → 回顾”的同一顺序。

## 边界

- 本次明确不解决：交互式系统教程、视频教学、自动代替用户绑定桌面。
- 新增数据及用途：无。
- 明确不采集：无新增采集。
- 必须由用户确认的决定：第一个工作流名称和完成首次设置。
- 数据不足、失败或权限缺失时的降级：不支持稳定桌面身份时跳过绑定步骤，进入手动工作流模式。

## 完整流程

1. 触发：第一次启动，或用户主动打开“新手教学”。
2. 唯一主要行动：先创建当前工作流；创建完成后查看被标记的当前下一步。
3. 反馈：工作流创建成功，并解释桌面绑定只能从状态栏完成。
4. 中断后的恢复：首次设置未完成但工作流已保存时，重新打开直接回到绑定教学。
5. 完成或退出：用户确认完成设置；之后可以从状态栏“更多”或时间轴帮助入口重看。
6. 验证：四阶段规则、一个必填输入、状态栏独占绑定和 README 路径均有自动回归。

## 技术与回归

- 业务规则位置：`FocusTraceGettingStartedContract`。
- 新增单元测试：`gettingStartedFollowsCreateBindWorkReviewWithoutAddingInputs`。
- 保护的既有回归测试：首次设置只有工作流名称一个必填输入；主窗口不能绑定桌面；状态栏和主窗口仍只有一个主要下一步。
- 性能工作负载与预算：无昂贵计算，不新增性能预算。
- 数据迁移与回退：无模型迁移；已有用户只会看到更新后的可选教学。

## 发布切片

首次创建后继续展示三步教学；可选帮助页显示同一四步路径；新增精简的新手文档并从 README 链接。
