# 决策：桌面绑定只在状态栏发生

- 状态：已采用
- 日期：2026-07-28
- 负责人：FocusTrace
- 主要产品支柱：看清 / 不丢

## 问题

用户从全屏工作桌面打开 FocusTrace 主窗口后，macOS 会切到 FocusTrace 所在的 Space。此时主窗口里的“绑定当前桌面”、首次启动自动绑定、需求开始处理时自动绑定等入口，拿到的是 FocusTrace 窗口所在的 Space，而不是用户刚才工作的全屏 Space。界面看似完成了绑定，实际却污染工作流归因，也让用户不知道应该在哪个入口操作。

状态栏面板会在用户当前所在的 Space 上展开，因此它才具备“当前桌面”的可靠语义。状态栏中的“Agent”入口实际只是保存返回点，并不连接或管理 Agent；模糊命名让用户无法判断它的用途。

## 预期结果与证据

- 用户只能在目标工作桌面的状态栏面板中创建或选择工作流并绑定当前 Space。
- FocusTrace 主窗口不再展示、暗示或隐式执行桌面绑定。
- 新建工作流与绑定桌面成为两个明确动作；首次创建不会把 FocusTrace 自己的 Space 误绑。
- 状态栏把原“Agent”入口显示为“离开前保存返回点”，用户能理解它用于保存回来后的第一步。
- 通过核心表面策略测试和仓库交互回归，证明主窗口不会暴露桌面绑定动作。

## 边界

- 本次明确不解决：自动把 FocusTrace 主窗口浮到全屏 Space；通过私有 API 自动跳回之前的 Space；全局快捷键绑定。
- 新增数据及用途：无。
- 明确不采集：窗口标题、网页地址、输入内容、Agent 输出以及返回点正文的报告内容。
- 必须由用户确认的决定：目标 Space 要绑定哪个工作流；返回点的下一步和可选提醒时间。
- 数据不足、失败或权限缺失时的降级：绑定失败时保持未绑定，不根据窗口、显示器位置或最近工作流猜测。

## 完整流程

1. 触发：用户位于真正工作的普通或全屏 Space，并点击 FocusTrace 状态栏图标。
2. 唯一主要行动：选择已有工作流，或新建工作流并绑定当前桌面。
3. 反馈：状态栏立即显示当前工作流和记录状态。
4. 中断后的恢复：绑定失败时仍保持未绑定；再次从目标 Space 的状态栏重试。
5. 完成或退出：用户可以从同一状态栏菜单解除当前桌面，主窗口仅管理工作流内容。
6. 验证：检查所有主窗口源码没有绑定入口；核心策略拒绝在主窗口呈现绑定行动；真实状态栏绑定后能解析到目标工作流。

## 技术与回归

- 业务规则位置：`FocusTraceCore/FlowGuidance.swift` 的工作流绑定表面策略；`ApplicationState` 的状态栏专用绑定入口。
- 新增单元测试：状态栏允许绑定、主窗口拒绝呈现绑定动作。
- 保护的既有回归测试：首次使用仍只有一个必要输入；状态栏保持紧凑；工作流创建、名称唯一、编辑、完成和删除不变。
- 性能工作负载与预算：不新增轮询和采集；状态栏仍只在展示时解析一次当前 Space。
- 数据迁移与回退：无模型迁移；回退只需恢复主窗口呈现策略和旧入口。

## 发布切片

删除主窗口所有显式和隐式绑定旁路，保留状态栏唯一绑定闭环；同时把状态栏的 Agent 模糊入口改为直接描述用户行为的返回点入口。
