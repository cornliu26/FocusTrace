# 决策：FocusTrace 只保留一个主窗口

- 状态：接受
- 日期：2026-07-25
- 负责人：FocusTrace
- 主要产品支柱：不丢

## 问题

主界面使用 `WindowGroup`，系统“新建窗口”和重复唤起可以复制多个 FocusTrace 主窗口。同一份工作上下文因此出现多个视觉副本，用户无法确定哪个才是当前状态。

## 预期结果与证据

无论从状态栏、Dock、系统通知还是键盘菜单唤起，FocusTrace 都只激活同一个主窗口。关闭后再次唤起应恢复该窗口，不创建第二份主界面。

## 边界

- 本次明确不解决：多文档、多账户或跨设备窗口同步。
- 新增数据及用途：无。
- 明确不采集：任何新的行为或窗口内容。
- 必须由用户确认的决定：无。
- 数据不足、失败或权限缺失时的降级：窗口无法恢复时重新创建唯一主窗口，不复制状态。

## 完整流程

1. 触发：用户从状态栏、Dock 或通知打开 FocusTrace。
2. 唯一主要行动：系统定位并激活主窗口。
3. 反馈：现有窗口前置并显示最新共享状态。
4. 中断后的恢复：窗口关闭或被遮挡后，同一路径再次唤起。
5. 完成或退出：关闭主窗口只隐藏界面，菜单栏记录继续工作。
6. 验证：窗口场景声明为单实例，系统新建窗口命令被移除，所有唤起路径使用同一窗口 ID。

## 技术与回归

- 业务规则位置：`FocusTraceCore/UXStabilityContract.swift` 的窗口契约和 `FocusTraceApp.swift` 的场景声明。
- 新增单元测试：唯一主窗口 ID、多窗口禁用契约。
- 保护的既有回归测试：菜单栏宽度、唯一主要下一步、通知打开需求收件箱。
- 性能工作负载与预算：无新增周期性工作。
- 数据迁移与回退：无数据变化；回退只需恢复旧场景声明。

## 发布切片

把主场景从 `WindowGroup` 改为单实例 `Window`，移除系统新建窗口入口和冗余设置窗口，统一唤起请求。
