# 决策：Codex 文件桥只登记一次，日常复盘不重复索要权限

- 状态：已采用
- 日期：2026-07-30
- 负责人：FocusTrace contributors
- 主要产品支柱：改善

## 问题

用户进入“回顾分析”或等待每日 Codex 复盘时，会反复看到文件访问授权。现有实现把“聚合报告目录登记”混进每次日报生成，并在每次进入回顾页时再次刷新生成工作区。Codex 定时任务因此每天尝试写入项目目录之外的 `Application Support/FocusTrace/CodexBridge`；即使桥接路径没有变化，也会重新触发权限边界。授权成本高于复盘本身，用户无法形成无打扰的每日回顾习惯。

## 预期结果与证据

首次接入时完成一次明确的桥接登记；之后进入回顾页和每日定时复盘不再写桥接配置。只有路径移动、登记丢失或用户显式要求重新连接时才再次登记。

验收证据：

- 普通日报运行只写当前项目的聚合报告目录，不创建或修改桥接文件；
- 带 `--register-bridge` 的显式运行才写 `bridge.json`；
- 重进回顾页不触发工作区刷新；
- App 启动刷新时，相同内容的脚本、指令和工具不重复替换；
- 现有报告读取、写回校验和聚合隐私测试保持通过。

## 边界

- 本次明确不解决：Developer ID 签名、公证、Codex 自身的全局权限策略或 macOS 对新签名版本的系统级重新授权。
- 新增数据及用途：不新增数据；只改变既有桥接配置的写入时机。
- 明确不采集：原始活动、窗口标题、URL、输入内容、系统权限历史和用户文件。
- 必须由用户确认的决定：首次连接以及路径失效后的重新登记。
- 数据不足、失败或权限缺失时的降级：保留本地分析；Codex 卡片显示尚未连接或等待报告，不循环请求权限。

## 完整流程

1. 触发：用户首次点击“在 Codex 中接入每日复盘”。
2. 唯一主要行动：App 创建聚合工作区并登记报告目录一次。
3. 反馈：App 说明 Codex 已打开；日报说明聚合报告已更新。
4. 中断后的恢复：登记已存在时继续沿用；生成文件相同则不重写。
5. 完成或退出：每日任务只在已授权工作区生成与写回聚合文件；用户可以不接入 Codex。
6. 验证：默认与显式登记两条脚本路径、回顾页源码契约、重复刷新策略和完整测试通过。

## 技术与回归

- 业务规则位置：`CodexWorkspaceRefreshPolicy`、`CodexWorkspaceInstaller`、两套 `generate-daily-report.sh` 文件契约。
- 新增单元测试：相同生成内容不替换、不同或缺失内容需要替换。
- 保护的既有回归测试：聚合报告隐私、历史日期参数、Codex 深链、写回校验和回顾展示。
- 性能工作负载与预算：减少进入回顾页和启动刷新时的文件写入；不增加常驻工作。
- 数据迁移与回退：已有 `bridge.json` 继续生效；回退只会恢复重复登记，不改变报告或本地 store。

## 发布切片

一个可独立回退的切片：移除回顾页的重复刷新、对生成文件采用内容一致性写入、将仓库日报桥接登记改成显式一次性动作，并让 App 生成工作区的日报完全复用首次登记。
